# Human evaluation and business-impact evidence

Status: pipeline and synthetic pilot implemented; no qualified reviewer study
or real business-outcome result is claimed until the protected workflow accepts
an independently collected dataset.

**Latest hosted evidence:** [Human evaluation and impact evidence run
30911931400](https://github.com/upgradedev/archon-cockroach-memory/actions/runs/30911931400),
successful on `main` at commit `93dfa73`, 2026-08-04. That run demonstrates the
gate executing and holding its two evidence tiers apart; it does not convert the
synthetic pilot into a reviewer study.

The canonical gate is
[`human-impact-evaluation.yml`](../.github/workflows/human-impact-evaluation.yml).
It deliberately separates two evidence tiers that cannot be relabelled by an
input file:

| Tier | Purpose | Permitted claim |
|---|---|---|
| `synthetic-pilot` | Exercise validation, paired statistics, confidence intervals, agreement, receipts, and negative controls on rights-safe authored records | “Synthetic analysis pipeline passed” |
| `qualified-human-study` | Analyze a preregistered, blinded study with consenting pseudonymous participants and at least three independent qualified reviewers | “Qualified human evaluation and bounded business-outcome study completed” |

Neither tier permits a production-scale corpus, customer outcome, production
business impact, ROI, cost saving, or risk-reduction claim. Those claim fields
are generated by the evaluator and are always `false`. The input schema has no
claim field; an added or renamed field fails closed.

## Ordinary pull-request gate

Pull requests and relevant `main` pushes run only
[`human-impact-synthetic-pilot.json`](../evals/human-impact-synthetic-pilot.json).
The fixture declares zero human reviewers, null protocol/preregistration/
authority/consent/signature fields, two synthetic raters, and four synthetic
paired trials. The gate fails if it is
relabelled as human, customer, production, or ROI evidence.

This pilot is useful implementation evidence, but its favorable sample values
are authored test inputs. They are not observed product impact.

## Qualified-study contract

A qualified dataset must use schema `1.0.0` and satisfy all of these controls:

- exact tier `qualified-human-study` and provenance
  `consenting-pseudonymous-human-study`;
- a protocol digest, preregistration digest, collection-authority digest,
  independent raw-evidence custody-receipt digest, and closed UTC collection
  window;
- blinded system labels plus randomized case and arm order;
- at least three distinct pseudonymous reviewer identifiers, each with an
  allowed finance/audit qualification, `independentOfProject=true`,
  `projectRole=none`, a unique consent digest, a unique independent identity
  attestation digest, and a unique Ed25519 public key;
- at least 20 B2/B4 paired cases from every reviewer and at least 50% of cases
  independently rated by two or more reviewers;
- every rating signed by its declared reviewer over the canonical payload from
  `ratingSignaturePayload`, including the SHA-256 binding of the complete study
  context and the reviewer's qualification, consent, identity-attestation, and
  public-key record;
- at least ten distinct consenting pseudonymous participants with paired
  baseline-versus-Archon task observations; and
- every paired trial signed by an independent declared reviewer over the
  canonical payload from `trialSignaturePayload`, including the same study
  and reviewer bindings; and
- every exclusion represented by a subject digest, bounded reason, collection
  timestamp, and independent reviewer signature over the same study and reviewer
  bindings; an empty exclusions array explicitly means that the collector
  reported no exclusions.

The gate rejects duplicate identities, consent receipts, identity attestations,
cross-purpose evidence-receipt digests, signing keys, ratings, participant/task
pairs, missing cohorts, timestamps
outside the collection window, unsigned records, invalid signatures, unexpected
fields, and unbounded input sizes. A B4 action-safety failure is retained in the
result and makes the gate fail; negative evidence is not discarded.

Cryptographic signatures prove control of distinct pseudonymous keys and make
post-collection rating changes detectable. They cannot prove a person's civil
identity. That remaining boundary is represented by the independently issued
identity-attestation digests and the protected human approval; it remains an
explicit receipt limitation.

## Protected execution

Qualified evaluation is a manual dispatch from exact current `main` through the
`human-evaluation` GitHub environment. Configure that environment with required
reviewers independent of the implementation author and a secret named
`HUMAN_IMPACT_DATASET_GZIP_B64`. The secret contains the gzip-compressed JSON
dataset encoded as base64. The dispatcher must provide:

- the SHA-256 of the uncompressed JSON;
- a non-secret approval reference;
- confirmation `EVALUATE-INDEPENDENT-HUMAN-STUDY`.

Before the protected dataset is decoded, the workflow also requires successful
same-SHA `main` push runs for CI, CodeQL, memory evaluation, and this workflow's
synthetic claim-boundary gate.

The runner decodes the dataset under `RUNNER_TEMP`, verifies the supplied digest
before evaluation. Decompression is capped at the evaluator's two-megabyte input
budget, and the runner deletes the entire raw-input directory in an `always()`
step before artifact upload. The secret, raw JSON, reviewer identifiers,
participant identifiers, ratings, signatures, and approval reference are never
uploaded. Validation errors use only schema positions and generic failure reasons,
so a rejected qualified dataset does not print pseudonymous identifiers into the
workflow log.

Because CI intentionally destroys its raw copy, the independent collection
custodian must retain the exact consented source dataset outside GitHub. A qualified
dataset carries the SHA-256 of that custodian's retention receipt, while the CI
input digest binds the exact JSON that was analyzed. Neither digest proves custody
by itself; together they make the evidence chain reviewable without publishing
pseudonymous records.

The protected environment and secret must be created through the approved
repository administration path. Do not copy the study dataset into the public
repository, a developer build directory, workflow input, issue, log, or commit.

## Machine-verifiable outputs

Every finalized run uploads only:

- `human-impact-results.json` — aggregate B2/B4 scores, paired outcome deltas,
  deterministic 2,000-resample case/participant-clustered 95% bootstrap
  intervals, interval-distance Krippendorff alpha,
  cohort counts, study/protocol/authority/custody digests, gates, claim ceiling,
  and limitations;
- `human-impact-input-manifest.json` — raw input digest/size and disclosure-safe
  cohort counts; and
- `human-impact-receipt.json` — exact source SHA, workflow identity, evidence
  tier, approval-reference digest, artifact digests/sizes, gates, claims, and a
  canonical JSON SHA-256 seal.

The raw dataset is intentionally not an artifact. A fail-closed
`not-finalized.json` marker remains when execution stops before a valid receipt.
Artifact success therefore cannot be confused with completed evidence.
Successful protected-main synthetic receipts and qualified-study receipts also
receive GitHub build-provenance attestations. A copied JSON file is not sufficient
evidence by itself: acceptance requires the artifact and attestation from the
corresponding GitHub Actions run at the receipt's exact source SHA.
Both attestations run in separate jobs that never check out or execute candidate
code. The pull-request evaluator and protected qualified-data job retain read-only
repository permissions and cannot request an OIDC token or write an attestation.
After downloading the receipt from its successful run, provenance can be checked
with `gh attestation verify human-impact-receipt.json --repo <owner/repository>`.

## Statistics and interpretation

Human metrics compare paired B4 minus B2 ratings for answer correctness,
evidence grounding, uncertainty calibration, and action safety. Agreement is
reported per rubric with interval-distance Krippendorff alpha. Human confidence
intervals resample distinct cases after averaging their reviewers, preventing an
extra rating from being treated as an independent case. Business metrics compare
paired baseline and Archon observations for time to decision, contradiction
misses, reviewer effort, unauthorized-action attempts, and task correctness;
their intervals resample participants after averaging repeated tasks. A positive
reported improvement always favors Archon; the receipt retains negative or null
outcomes without selective filtering.

The deterministic bootstrap makes an exact input reproducible, not universally
representative. Results apply only to the preregistered sample, tasks, protocol,
and exact application SHA.
